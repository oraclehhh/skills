# Cheatsheet: Judgment and Decision Under Uncertainty

## Fast Diagnosis

| If you see... | Suspect... | Do this |
|---|---|---|
| A first number dominates later estimates | Anchoring | Make an independent estimate; compare with base rates |
| A vivid example feels statistically important | Availability | Ask for frequency data and comparison classes |
| A case "sounds like" a category | Representativeness | Check base rates and sample size |
| A coherent story explains everything | Explanation bias | Generate rival stories and disconfirming tests |
| A streak feels meaningful | Pattern over-detection | Check randomness, sample size, and regression |
| A prior investment drives continuation | Sunk cost | Ignore unrecoverable costs; compare future options |
| Different wording flips preferences | Framing | Reframe as gains, losses, percentages, and natural frequencies |
| A model is rejected because it feels too simple | Intuition overconfidence | Benchmark against a simple linear model |

## Decision Procedure

1. Define the decision, not just the problem.
2. List feasible alternatives, including "do nothing."
3. State the outcome dimensions that matter.
4. Estimate base rates before case-specific evidence.
5. Build a decision tree or probability table for uncertainty.
6. Assign utilities or ranked priorities.
7. Compute or compare expected consequences.
8. Run sensitivity checks: what estimate would change the choice?
9. Check for biases: anchoring, availability, representativeness, sunk cost, loss aversion, framing.
10. Choose the option that remains best under plausible errors.

## Probability Translation

| Confusing form | Better form |
|---|---|
| "The test is 95% accurate" | Out of 1,000 people like this, how many true positives and false positives? |
| "This story is likely" | What is the base rate for this class of events? |
| "The odds changed after a streak" | Are trials independent? If yes, previous outcomes do not rebalance future ones |
| "X caused Y" | What comparison group or counterfactual supports that claim? |

## Preference Audit

| Question | Why it matters |
|---|---|
| Would I choose the same option if framed as a loss? | Detects loss aversion and framing |
| Would I pay the same amount as I demand to give it up? | Detects endowment and valuation gaps |
| Am I ranking, pricing, choosing, or matching? | Different elicitation methods construct different preferences |
| What future cost and benefit remain? | Removes sunk-cost pressure |
| What regret am I trying to avoid? | Separates utility from anticipated emotion |

## Model vs. Judgment Rule

Use a simple model when:
- Cue values can be listed.
- Past cases exist.
- Consistency matters.
- The judge cannot articulate a valid exception.

Trust expert override only when:
- The expert sees a valid cue absent from the model.
- The cue has known diagnostic value.
- The override rule is explicit before the outcome is known.

## Robust Choice Rule

Prefer the option that:
- Does well under base-rate assumptions.
- Does not rely on one vivid story being true.
- Has bounded downside if estimates are wrong.
- Can be revised after feedback.
- Makes uncertainty visible rather than hiding it.
