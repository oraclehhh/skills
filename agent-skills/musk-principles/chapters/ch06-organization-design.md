# Chapter 6: 设计组织架构

## Core Idea
组织结构应该服务于创造，而不是服务于管理者的舒适。打破部门墙、简化沟通，并为创新保留合理容错空间。

## Frameworks Introduced
- **Anti-Silo Design**: remove barriers between people who must solve the same problem.
- **Communication Simplification**: let information travel directly.
- **Fault-Tolerant Innovation**: allow mistakes that generate learning without tolerating negligence.

## Key Concepts
- **Silo**: organizational boundary that blocks problem solving.
- **Direct communication**: maker-to-maker information flow.
- **Tolerance for failure**: permission to experiment responsibly.

## Mental Models
Use "organization as circuit." Every unnecessary relay adds delay and signal loss.

## Anti-patterns
- **Chain-of-command theater**: information must climb and descend hierarchy before action.
- **Blameless mediocrity**: using tolerance as an excuse for repeated poor execution.

## Worked Example
If engineering and manufacturing disagree through managers, put both teams at the production problem and let them revise the design together.

## Key Takeaways
1. Structure should reduce latency.
2. Innovation needs room to test.
3. Bureaucracy is a technical liability.
