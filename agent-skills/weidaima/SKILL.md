# 中文伪代码生成 Skill

## 目标

将一份源代码文件，逐行翻译为纯中文伪代码文档，帮助用户像查字典一样快速定位每一行代码的中文含义。

## 核心原则

1. **逐行对应**：中文伪代码的每一行必须对应源代码的一行，不能合并、不能总结、不能跳过。
2. **纯中文**：不夹杂英文代码。变量名、函数名全部翻译为中文。常量值（数字、字符串字面量）保留原样。
3. **标注源代码行号**：每个函数/段落的标题标注对应源代码的行号范围，例如 `函数：计算RD（第167~171行）`。
4. **写"为什么"**：在关键步骤后面用 `#` 注释解释为什么这么做，不只是说做了什么。

## 输出格式

```
============================================================
函数：中文函数名（第XX~YY行）
============================================================
定义 中文函数名(参数1, 参数2):
    # 目的：一句话说明这个函数解决什么问题
    变量 = 操作(...)
    # 为什么这么做的解释
    如果 条件:
        # 为什么要判断这个条件
        操作
    返回 结果
```

### 注释规范

- 每个函数开头用 `# 目的：` 一句话说明功能
- 条件判断后面解释"为什么要判断"
- 数学公式后面解释"这个公式在算什么、物理含义是什么"
- 阈值/魔数后面解释"为什么是这个值"
- 跳过/过滤操作后面解释"什么情况会被跳过、为什么要跳过"

### 注释示例

```
如果 tap数组大小 < 2:
    # ITI 是相邻两次tap的间隔，至少需要2个tap才能算出1个间隔
    返回 空浮点数组

片段列表 = [单block的ITI秒(block) 对于 block 在 blocks列表 如果 block长度 >= 2]
# 只对 tap 数 >= 2 的 block 算 ITI，因为少于2个tap算不出间隔

返回 中位数(绝对值(iti - 理想节拍间隔秒))
# RD = 每个ITI偏离理想节拍(0.5秒)多远，取中位数
# 衡量被试打节拍的准确度
```

## 工作流程

1. 读取用户指定的源代码文件
2. 识别语言，按以下规则分块：
   - Python/JS/TS/Java/Go：以函数定义（def/function/func）或类定义为分界
   - MATLAB：以 `function` 关键词为分界；脚本文件（无 function 声明）以 `%%` 节注释为分界
   - 无函数结构的脚本：以连续空行（≥2行）或 `# ---` / `%%` 风格注释为分界
   - 单函数长文件：每 50 行为一块
3. **🔴 CHECKPOINT**：翻译第一个块后暂停，展示给用户确认风格和粒度是否满意，再继续后续块
4. 对每块标注源代码行号范围
5. 逐行翻译为中文伪代码
6. 在关键步骤添加"为什么"注释
7. 文件超过 200 行时，每翻译完 3 个块暂停展示阶段性结果
8. 输出为 `.txt` 文件，文件名格式：`{原文件名}_中文伪代码.txt`

## 异常处理

| 触发条件 | 一线修复 | 仍失败时兜底 |
|----------|----------|-------------|
| 非 Python 代码（对照表不覆盖） | 用通用翻译规则：保留控制流关键词中文化，库函数按「动词+宾语」格式翻译 | 标注 `[待确认]` 请用户补充该语言的术语偏好 |
| 文件超过 500 行 | 分批输出，每批 ≤150 行伪代码，批间展示进度 | 询问用户是否只翻译指定函数/行号范围 |
| 一行源代码包含多个语句（分号分隔） | 拆为多行伪代码，每个语句独立一行，标注同一行号 | — |
| 变量名/函数名无法翻译为有意义中文 | 用「音译+括号原名」格式，如：回调函数(callback) | 保留原名并用 `[原名]` 标记 |
| 代码中已有中文注释 | 保留原注释，用 `[原注释]` 前缀区分，不与伪代码注释混淆 | — |
| 宏定义/预处理指令（C/C++） | 翻译为「预处理：{动作}」格式 | 标注 `[跳过：预处理指令]` 并说明原因 |
| 装饰器/注解（@开头） | 翻译为「装饰：{功能说明}」，置于函数定义前一行 | — |
| MATLAB 矩阵索引（A(1:end, :)）| 翻译为「取 A 的第1行到最后一行，所有列」，用自然语言描述切片范围 | 复杂索引加 `[索引说明]` 注释 |
| MATLAB end 关键词歧义（循环 end vs 函数 end） | 根据缩进层级判断：函数体结束翻译为「函数结束」，循环/条件结束翻译为对应的「循环结束」「条件结束」 | — |

## 不要做的事

- 不要合并多行为一行总结
- 不要只写"做什么"不写"为什么"
- 不要在中文伪代码里插入英文代码
- 不要遗漏任何一行逻辑代码
- 不要改变原代码的缩进层级和结构
- 不要把注释翻译成"这里是XXX的处理"这种空话——必须说清为什么
- 不要对 import/include 语句只写"导入XXX"就完事——要补充「用途：提供YYY功能」
- 不要把多个短赋值语句合并为一句"初始化若干变量"
- 不要自作主张重排代码顺序（即使你觉得原顺序不合理）
- 不要用"等等"、"以此类推"、"类似地处理"省略重复逻辑——每一行都必须显式写出
