# Argument, Architecture, and Prose Repair

## 1. 论证修复

为每个核心结论检查：

`研究问题/假设 → 设计与测量 → 分析 → 结果 → 解释 → 结论`

修复缺失桥梁、设计—结论错配、分析层级混用、替代解释遗漏和跨章节 claim-strength drift。区分直接结果、证据约束解释、机制推论和广义理论；不要从直接结果跳到未检验机制。

## 2. 结构修复

只有在用户已授权相应范围时进行大幅结构调整。

- Results：按 scientific question → evidence → quantitative result → immediate implication 组织，避免统计清单、重复题注和过多文献讨论。
- Discussion：围绕主要发现、理论含义、文献关系、竞争解释、边界、局限和贡献组织，不机械重复 Results。
- Introduction：压缩无功能背景，校准 gap 与 novelty，连接理论和当前设计，不提前写完整 Discussion。
- Abstract：保持 context → unresolved problem → approach → main result → implication，并与正文数字和强度一致。
- Title：准确、简洁、非宣传；间接或模型派生 construct 不得写成直接测量。
- Figure-led narrative：为每张图记录 scientific question、key result、evidence ceiling 和 narrative role；不得隐藏矛盾图或改变图中数据。

同一 finding 可以在 Abstract、Results、Discussion、Conclusion 出现，但应分别承担总结、证据、解释和综合功能。仅换词重复时删除或合并。

## 3. Nature 或目标期刊深度 revision

仅在用户明确指定目标期刊并授权深度修改时启用。先区分：当前主张、maximum defensible claim、目标期刊允许的最强表达和明确禁止的 overclaim。写作不得超过 maximum defensible claim。

广泛意义应来自科学问题、概念连接或方法价值，而非把单一样本、任务、文化、物种、数据集或频段推广为普遍规律。

## 4. 替代解释

不要只强化作者偏好的解释。说明现有结果与哪些解释一致、当前设计能否区分，以及需要什么未来检验。不得把 future analysis 写成已完成结果。

## 5. AI 风格风险修复

目标是 scientific-function-driven prose，不是规避 detector。可以修复模板化总结、重复 `These findings suggest`、机械 `Taken together`、not-X-but-Y 模板、元话语、审稿回复残留、过度防御、宣传性语言、重复段落功能和低信息密度。

关键词只用于定位，不自动删除。若句子承担必要证据边界，应保留或精确压缩。不要随机换同义词、故意加错误、随机改变句长、删除所有过渡或机械替换 `suggest/indicate`。

优先动作：

1. `DELETE` 无新增信息的修辞脚手架；
2. `MERGE` 重复结论或段落功能；
3. `MOVE` 放错章节的内容；
4. `REWRITE` 使变量、条件、方向和含义成为句子核心；
5. 保留必要限定语、引文、阴性结果和局限。

## 6. Reviewer comments

对每条审稿意见记录：Comment ID、科学问题、所需证据、修复动作、稿件位置和状态。状态使用 `ADDRESSED`、`PARTIALLY_ADDRESSED`、`NOT_ADDRESSED`、`AUTHOR_DECISION_REQUIRED` 或 `EVIDENCE_NOT_AVAILABLE`。审稿意见不是事实来源，也不能授权突破证据边界。
